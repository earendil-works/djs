## Goal
ARCH.md "regex": our own backtracking engine, compiled to compact regex bytecode,
fuel-metered and **resumable** (catastrophic backtracking is a timeout, not a hang, and
a match can be suspended and snapshotted). This issue builds the engine as a
self-contained module over code-unit slices. Hooking it into `RegExp` objects and the
heap is done later, with the builtins.

## Acceptance criteria
- [ ] Parser for ES2025 pattern syntax, both non-unicode (strict, no Annex B) and
      `u` modes: alternation, quantifiers (greedy/lazy, `{n,m}`), classes and escapes,
      `\d\w\s\b\B`, backreferences (numbered and named), groups (capturing, named,
      non-capturing), lookahead, lookbehind, `.` with and without `s`, `^$` with and
      without `m`, `i` case-insensitivity (the spec's Canonicalize: simple case folding
      in u-mode, toUppercase-based otherwise), `y` and `g` handled by the caller via a
      start index, duplicate named groups (in different alternatives), and modifiers
      `(?i:...)` if cheap. Early errors as SyntaxError with QuickJS's messages.
- [ ] `v` flag (class set operations, string literals in classes): design for it; it may
      be a follow-up if large.
- [ ] Unicode property escapes `\p{..}`: put them behind a cargo feature
      (`regexp-unicode-props`, off by default for now) because of the table size. The
      base engine must not pull the tables in. Implement it in this issue only if
      small; otherwise make it a follow-up.
- [ ] Case mapping tables (simple case folding, and toUppercase/toLowercase including
      the special multi-char ones that `String.prototype.to*Case` will need) generated
      into `unicode/` by the existing generator (same UCD version, D1031). Record the
      table sizes.
- [ ] Compiler to compact regex bytecode (a `Vec<u8>` or `Vec<u32>` now, later stored
      in a heap cell, so it must contain no pointers). Include the capture count, group
      names and flags in a header.
- [ ] Matcher: explicit backtrack stack (no Rust recursion), over `&[u8]` (Latin-1) and
      `&[u16]` input. API shaped like `exec(prog, input, start) -> Match | NoMatch |
      OutOfFuel(state)`, where the state is plain data (it is serializable: integers
      and the backtrack stack as a `Vec<u32>`), so that it can be moved into the arena
      and resumed later. Fuel is charged per step. Captures as UTF-16 index pairs.
- [ ] A step and backtrack-stack limit gives a clean error (not an OOM, not a hang).
- [ ] Tests: unit tests per feature. A qjs-generated corpus (`tests/data/regexp/`,
      generated by a checked-in script that runs `~/Development/dquickts/qjs`):
      thousands of (pattern, flags, input, lastIndex) cases → match/captures, or
      SyntaxError. Include pathological patterns (`(a*)*b` and similar) to check fuel,
      suspend and resume (resuming in steps gives the same result as one run).
      Optionally, an ignored test that extracts regex literals from test262
      `built-ins/RegExp` and `language/literals/regexp` and checks that we parse
      (valid/invalid) the same as qjs.
- [ ] Rough numbers in the Log: compile and match speed on a few typical patterns, and
      the wasm size of the module.

## Notes
- QuickJS `libregexp.c` (read-only, `~/Development/dquickts`) is the reference for
  semantics and error messages. Its design (bytecode + explicit stack) is close to what
  we want, but do not port it blindly: resumability and no pointers are hard
  requirements.
- Keep the module free of heap/VM dependencies, so it can be tested in isolation.
- Code size matters (ARCH G2). Note in the Log what dominates.
