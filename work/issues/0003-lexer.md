## Goal
A complete, fast, allocation-free ECMAScript lexer for the single-pass compiler (ARCH.md
"Compiler (no AST)"), ready for the TypeScript type skipper later.

## Acceptance criteria
- [ ] Input is UTF-8 `&[u8]`. Positions are `u32` byte offsets; line/column come from a
      lazily built line table (for error messages and line tables).
- [ ] The lexer state is a small `Copy` struct, so it can be checkpointed and rewound
      cheaply (ARCH: lookahead scanning and rewind).
- [ ] Tokens: all punctuators; identifiers including `\u` escapes; reserved words (an
      escaped reserved word is flagged so the parser can reject it); contextual keywords
      (`let static yield await async of get set target meta` plus the TS ones: `type
      interface declare abstract readonly enum namespace module keyof infer is asserts
      satisfies override implements private protected public unique global accessor
      out`) recognized as identifiers with a fast keyword id; private names `#x`.
- [ ] Numeric literals: decimal, `0x`/`0o`/`0b`, separators (with all the placement
      rules), exponents, the BigInt `n` suffix. Legacy octal and `08`/`09` are a
      SyntaxError (always strict). The lexer validates syntax and gives the span plus
      the kind; the f64 value comes from `crate::num` (issue 0004), not the lexer.
      Expose the span in a form the number parser can use (separators stripped, or a
      helper that strips them).
- [ ] String literals: all escapes, line continuations, `\u{…}`, lone surrogates
      allowed. Legacy octal escapes and `\8` `\9` are a SyntaxError. Cooking writes into a
      caller-provided `Vec<u16>` and reports whether the result is all Latin-1 (so the
      heap can store one-byte strings). The fast path, a literal with no escapes, avoids
      cooking.
- [ ] Templates: head/middle/tail scanning driven by the parser, cooked and raw values,
      and invalid escapes reported as "cooked undefined" (for tagged templates), not as an
      error.
- [ ] Regex literals: the parser calls `rescan_as_regex()` when `/` or `/=` appears where
      an expression starts. It returns the body and flags spans. Only the flag
      characters and the basic body structure (classes, escapes, terminators) are
      validated here.
- [ ] `>`: emitted as a single-character token. The parser calls `rescan_greater()` to
      form `>>`, `>>>`, `>=`, `>>=`, `>>>=` (tsc's approach, needed for TS generics).
- [ ] Whitespace per spec (including Unicode Zs, BOM, NBSP), line terminators (including
      U+2028/U+2029), a `newline_before` flag on every token (for ASI and restricted
      productions), single/multi-line comments (a multi-line comment containing a
      newline sets the flag), and a hashbang at the very start. No HTML comments (Annex
      B).
- [ ] Unicode ID_Start / ID_Continue (plus `$`, `_`, ZWNJ, ZWJ): compact range tables
      generated by a checked-in script from UCD data (fetched into `vendor/`). Use the
      Unicode version test262 at the pinned commit expects (check dquickts'
      `unicode_download.sh`). The generated table is checked in.
- [ ] Errors: a `LexError` with a position and a message. Use QuickJS's message wording
      where it is easy to match.
- [ ] Unit tests for every category above. Also an `#[ignore]`d test that lexes every
      file in `vendor/test262/test` (if present) and asserts no panic. Negative tests
      may produce errors.
- [ ] A rough throughput number on a large JS file (recorded in the Log). Target: no
      allocation per token, well over 50 MB/s native.

## Notes
- No heap dependency: the lexer must not know about the VM heap. Identifier and string
  values are handed out as spans or cooked buffers. Interning happens in the compiler
  (issue 0006).
- Keep TS-specific logic out of the lexer except for the contextual keyword list. The
  type skipper (P3) works at token level on top of this lexer.
- Look at QuickJS's lexer in `~/Development/dquickts/quickjs.c` (`next_token`,
  `js_parse_string`, `js_parse_template_part`, `js_parse_regexp`) for edge cases.
- test262 is fetched by issue 0002 (running in parallel). If `vendor/test262` does not
  exist yet, you can run `git clone` of the pinned commit yourself into `vendor/test262`
  (D003), but do not write the fetch script; 0002 owns it.
