## Goal
A complete, fast, allocation-free ECMAScript lexer for the single-pass compiler (ARCH.md
"Compiler (no AST)"), ready for the TypeScript type skipper later.

## Acceptance criteria
- [x] Input is UTF-8 `&[u8]`. Positions are `u32` byte offsets; line/column come from a
      lazily built line table (for error messages and line tables).
- [x] The lexer state is a small `Copy` struct, so it can be checkpointed and rewound
      cheaply (ARCH: lookahead scanning and rewind).
- [x] Tokens: all punctuators; identifiers including `\u` escapes; reserved words (an
      escaped reserved word is flagged so the parser can reject it); contextual keywords
      (`let static yield await async of get set target meta` plus the TS ones: `type
      interface declare abstract readonly enum namespace module keyof infer is asserts
      satisfies override implements private protected public unique global accessor
      out`) recognized as identifiers with a fast keyword id; private names `#x`.
- [x] Numeric literals: decimal, `0x`/`0o`/`0b`, separators (with all the placement
      rules), exponents, the BigInt `n` suffix. Legacy octal and `08`/`09` are a
      SyntaxError (always strict). The lexer validates syntax and gives the span plus
      the kind; the f64 value comes from `crate::num` (issue 0004), not the lexer.
      Expose the span in a form the number parser can use (separators stripped, or a
      helper that strips them).
- [x] String literals: all escapes, line continuations, `\u{…}`, lone surrogates
      allowed. Legacy octal escapes and `\8` `\9` are a SyntaxError. Cooking writes into a
      caller-provided `Vec<u16>` and reports whether the result is all Latin-1 (so the
      heap can store one-byte strings). The fast path, a literal with no escapes, avoids
      cooking.
- [x] Templates: head/middle/tail scanning driven by the parser, cooked and raw values,
      and invalid escapes reported as "cooked undefined" (for tagged templates), not as an
      error.
- [x] Regex literals: the parser calls `rescan_as_regex()` when `/` or `/=` appears where
      an expression starts. It returns the body and flags spans. Only the flag
      characters and the basic body structure (classes, escapes, terminators) are
      validated here.
- [x] `>`: emitted as a single-character token. The parser calls `rescan_greater()` to
      form `>>`, `>>>`, `>=`, `>>=`, `>>>=` (tsc's approach, needed for TS generics).
- [x] Whitespace per spec (including Unicode Zs, BOM, NBSP), line terminators (including
      U+2028/U+2029), a `newline_before` flag on every token (for ASI and restricted
      productions), single/multi-line comments (a multi-line comment containing a
      newline sets the flag), and a hashbang at the very start. No HTML comments (Annex
      B).
- [x] Unicode ID_Start / ID_Continue (plus `$`, `_`, ZWNJ, ZWJ): compact range tables
      generated by a checked-in script from UCD data (fetched into `vendor/`). Use the
      Unicode version test262 at the pinned commit expects (check dquickts'
      `unicode_download.sh`). The generated table is checked in.
- [x] Errors: a `LexError` with a position and a message. Use QuickJS's message wording
      where it is easy to match.
- [x] Unit tests for every category above. Also an `#[ignore]`d test that lexes every
      file in `vendor/test262/test` (if present) and asserts no panic. Negative tests
      may produce errors.
- [x] A rough throughput number on a large JS file (recorded in the Log). Target: no
      allocation per token, well over 50 MB/s native.

## Notes
- No heap dependency: the lexer must not know about the VM heap. Identifier and string
  values are handed out as spans or cooked buffers. Interning happens in the compiler
  (issue 0006).
- Keep TS-specific logic out of the lexer except for the contextual keyword list. The
  type skipper (P3) works at token level on top of this lexer.
- Look at QuickJS's lexer in `~/Development/dquickts/quickjs.c` (`next_token`,
  `js_parse_string`, `js_parse_template_part`, `js_parse_regexp`) for edge cases.
- test262 is fetched by issue 0002 (running in parallel). If `vendor/test262` does not
  exist yet, you can run `git clone` of the pinned commit yourself into `vendor/test262`
  (D003), but do not write the fetch script; 0002 owns it.

## Log

- 2026-11-01: Read the docs and QuickJS's lexer (`next_token`, `js_parse_string`,
  `js_parse_template_part`, `js_parse_regexp`, `parse_ident`). Probed qjs for error
  messages and column semantics (columns count code points; lines count LF only).
- Unicode: dquickts uses 17.0.0. `scripts/gen-unicode.py` downloads
  `DerivedCoreProperties.txt` and `extracted/DerivedGeneralCategory.txt` into
  `vendor/unicode/17.0.0/` of the primary checkout (with curl: Python's urllib has no CA
  store here, and unicode.org sometimes answers 520, hence retries) and writes
  `crates/djs-core/src/unicode/tables.rs` (packed `u32` ranges, 1141 words, ~4.5 KB).
  `--check` verifies the checked-in file.
- Lexer in `crates/djs-core/src/lexer/`: `mod.rs` (dispatch, trivia, identifiers,
  UTF-8 decoding), `token.rs` (`TokenKind`, `Kw`, `Token`, `Span`), `number.rs`,
  `string.rs` (strings, templates, cooking), `regex.rs`, `line_table.rs`, `tests.rs`.
  Design recorded as D1030 (API shape), D1031 (Unicode tables), D1032 (line table).
- `enum` is a reserved-word token kind (ECMAScript always reserves it), although the
  issue lists it with the TS contextual keywords. Its `Kw::Enum` id is there either way.
  Extra `Kw` ids beyond the list: `as from package eval arguments constructor using`
  (needed by the parser for imports/exports, strict-mode checks and class bodies).
- Escaped identifiers: `\uD835\uDC00` is rejected (each escape must be an identifier
  code point on its own, per spec). Escaped keyword ids are computed without allocating
  (stack buffer of 11 bytes).
- Invalid UTF-8 is an error everywhere, comments included (QuickJS skips it there).
- test262 sweep (`cargo test -p djs-core --release lex_test262 -- --ignored --nocapture`):
  53934 files, no panics. Every token is cooked too. Errors only in 276 negative tests,
  8 sloppy-mode tests (legacy octal), and 4 division tests where the test driver's
  regex-vs-division heuristic guesses wrong (`{...} / 1`), which are allowlisted. The
  test asserts there is nothing else. I reviewed the negative tests in lexical
  directories that lex without error: all are parser-level errors (escaped/reserved
  words, template escapes in untagged templates, regex pattern errors, `-->`, ...).
- Throughput (`--release`, `lex_throughput`, M-series Mac, includes a small driver for
  regex/template rescans): typescript.js 9.1 MB at ~490-580 MB/s (~12-14 ns/token),
  mermaid.min.js 6.5 MB at ~360-430 MB/s, all of test262 concatenated (86 MB) at
  ~600-740 MB/s. No allocation per token. Run it on any files with
  `DJS_LEX_BENCH=/abs/a.js:/abs/b.js`.
- Also a randomized fragment-soup test (50k inputs, in the normal test run) that checks
  no panics and consistent cooking.

## Follow-ups

- Parser (0006) duties the lexer leaves to it: reject `is_escaped_reserved()`
  identifiers as references/bindings, escaped contextual keywords used as keywords
  (`is_contextual` checks this), `Kw::is_strict_reserved()` names as bindings, untagged
  templates with `INVALID_ESCAPE` (error from `cook_template`), `#constructor`, and an
  identifier or number directly after a regex literal (`/a/g\u0069`).
- TS type skipper (P3): tsc also has `reScanLessThanToken` to split `<<` in
  `f<<T>(x: T) => T>()`. Not needed for anything yet; add a `rescan_less` when the
  skipper needs it.
- `scripts/gen-unicode.py --check` could join the gate once fetching vendor data is a
  standard setup step (it needs the network on first run).
- The regex compiler (P5) validates patterns; the lexer only checks structure and flags.
- If difftests ever compare error positions for sources with lone CR or LS/PS, D1032
  differs from QuickJS there (QuickJS counts LF only).

## Result

Landed `djs_core::lexer` and `djs_core::unicode`:

- `Lexer::new(src: &[u8]) -> Result<Lexer, LexError>` (skips a hashbang), then
  `next_token() -> Result<Token, LexError>`. `Lexer` is `Copy`: checkpoint by copying,
  rewind by assigning back. `Token` is 12 bytes: `kind`, `kw`, `flags`
  (`NEWLINE_BEFORE`, `HAS_ESCAPE`, `HAS_CR`, `INVALID_ESCAPE`, `HAS_SEPARATOR`),
  `start`, `end`.
- Parser-driven rescans: `rescan_as_regex(tok)` for `/` and `/=`,
  `rescan_template_continuation(tok)` for the `}` closing a substitution,
  `rescan_greater(tok)` to form `>>`, `>>>`, `>=`, `>>=`, `>>>=`.
- Values: `ident_value` / `cook_ident` (UTF-8; borrows the source without escapes),
  `string_content` (fast path) / `cook_string` (UTF-16 into a caller `Vec<u16>`,
  returns "all Latin-1"), `template_content` / `cook_template` (`Err` = cooked
  undefined) / `template_raw`, `number_literal` (base, digits with `_` still in, BigInt
  flag; plus `strip_separators`), `regex_parts` (body and flags spans).
- `LineTable::new(src)` with `line(pos)` and `line_col(src, pos)` (1-based, columns in
  code points), built on demand.
- `unicode::{is_js_id_start, is_js_id_continue, is_js_whitespace,
  is_js_line_terminator, ...}` from generated UCD 17.0.0 tables.
- Errors: `LexError { pos, message }` with QuickJS messages ("invalid number literal",
  "octal literals are deprecated in strict mode", "unexpected end of string",
  "malformed escape sequence in string literal", "unexpected end of regexp",
  "invalid regular expression flags", ...).

Known gaps: none against the acceptance criteria. See Follow-ups for what the parser
must check.
