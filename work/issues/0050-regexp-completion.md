## Goal
Finish RegExp so it can move to the active group: the 0033 follow-ups.

## Acceptance criteria
- [ ] `\p{…}` / `\P{…}` Unicode property escapes (General_Category, Script,
      Script_Extensions, binary properties, and the v-flag properties of strings), from
      UCD 17 tables generated by the existing script. This is behind the
      `regexp-unicode-props` cargo feature from D1112; decide with numbers whether it
      should be on by default (measure the table size against the 0043 size budget and
      record the decision). Case-insensitive matching with properties per spec.
- [ ] Greedy loops over a single character or class (`\D+`, `\s*`, `[a-z]*`, `.*`) use one
      compact backtrack frame (counter + position) instead of one per iteration. This
      fixes the 3 test262 overflows, makes suspension cheaper, and speeds up the email
      pattern from 0011's benchmarks (record before/after).
- [ ] The compiled program is cached per regex literal site (spec: each evaluation still
      creates a fresh RegExp object, but the pattern compile can be shared), and RegExp
      fast paths for `split`/`replace` with an unmodified RegExp (the spec-observable
      lookups must be checked like the D1351 original-function checks).
- [ ] Promote built-ins/RegExp, the regexp-* features, language/literals/regexp,
      RegExpStringIteratorPrototype and the Symbol.match/matchAll/replace/search/split
      features from later to active. Report the numbers before and after the move.
- [ ] JSON.parse source text access (`json-parse-with-source`: `{source}` in the reviver
      context, `JSON.rawJSON`, `JSON.isRawJSON`) if cheap; otherwise a follow-up.
- [ ] Ratchets updated, and corpus cases for property escapes.

## Follow-ups
- JSON.parse source text access (json-parse-with-source: the reviver's `{source}`,
  JSON.rawJSON and JSON.isRawJSON) is not cheap. It needs:
  - a parse mode that records the source text of every primitive in a snapshot tree the
    reviver walks next to the values (json/parse.rs, the heap's area);
  - a raw-JSON object kind with [[IsRawJSON]];
  - stringify support for it in both paths.
  My estimate is half a day to a day; about 40 test262 tests (later group).
- `%RegExpExecRaw` copies the program out of its cell on every call. That is O(program)
  per exec: 11 KB for `\p{L}`, 136 KB for `\p{RGI_Emoji}` with its 3,700 strings. A
  matcher that reads the words in place, or a per-run cache, would remove the copy.
- Literal evaluation is still 8x qjs (object creation plus the exec protocol in the
  builtin language): a candidate for a `test`/`exec` fast path on pristine RegExps.
- Properties of strings could go behind their own feature if size gets tight (18 KB).

## Result
- `\p{..}`/`\P{..}`: all the properties, with qjs semantics. Feature
  `regexp-unicode-props`, on by default (D1500).
- Loops over one character use a single backtrack frame, skip hopeless positions, and
  skip failed runs when the loop starts the pattern (D1501).
- Regex literals compile once (D1502).
- split and global string replace on unmodified RegExps run as suspendable leaves at
  about qjs speed (D1503).
- RegExp is in the active group: 34,489 / 34,904 active passing.
- Not done: JSON.parse source text access (follow-up).
