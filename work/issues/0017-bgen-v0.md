## Goal
ARCH.md "Builtins" → "The builtin language": the build-time compiler for the strict TS
subset, first with the **bytecode backend only** (check the subset, erase the types, emit
plain JS with `%Intrinsic(...)` calls in djs's privileged syntax, docs/compiler.md 7.3).
The Rust state-machine backend comes later (perf track), but nothing here may block it.

## Acceptance criteria
- [ ] Implementation language decision (record it as a decision). Options: (a) Rust with a
      parser crate (for example oxc), plus our own type checking for the subset, or (b)
      TypeScript on node using the TypeScript compiler API, which gives real type
      information (needed for the numeric-type rules and for the
      reentrant-intrinsic analysis). Constraint: a normal `cargo build` of djs must not
      need node. Generated output is checked in, and bgen only runs to regenerate (the
      gate checks freshness when the tool is available). Note that the installed
      TypeScript in pi-private is 7.x (native); check its API situation before choosing
      (b), and pin a version in `builtins/package.json` if you use one.
- [ ] `builtins/intrinsics.d.ts`: branded numeric types (`i32`, `u32`, `f64`), `Value`,
      `Obj`, `Str`, `Sym`, `Fn`; intrinsic declarations tagged `@leaf` / `@reentrant`;
      and a starter set of intrinsics that the P1 prelude needs (ToPrimitive pieces,
      property get/set/define, call, construct, type checks, throwing errors). It is fine
      if the list is small; it grows with the builtins.
- [ ] `builtins/tsconfig.json`, so editors and tsc type-check `builtins/*.ts`.
- [ ] Subset checker, with clear errors and source positions: the rules in ARCH
      ("The subset") — no closures over mutable locals, no `arguments`/`eval`, no
      generators, explicit types where required, the numeric rules (operations whose
      JS and Rust meanings differ are rejected), and calls only to intrinsics, other
      builtin functions, or user callables via `call(...)`.
- [ ] Resume-point inference (needed later for Rust, useful now as a check): for each
      function, list the call sites that may run user code, and mark functions as
      leaf/reentrant transitively. Output it as a report (`bgen --report`).
- [ ] JS emitter: types erased, `%Name(...)` intrinsic syntax, one output file
      (`builtins/gen/prelude.js` or similar, checked in) with a stable order and a
      `// generated` header. Builtin installation metadata (which global or prototype
      gets which function, the property attributes, `name` and `length`) is emitted in a
      form the VM can consume. Coordinate the exact format via the issue log; P1-2 is the
      first consumer.
- [ ] A couple of real example builtins written in the subset, for example
      `Array.prototype.map`, `forEach`, `indexOf`, `join` and `ToPrimitive`, with their
      generated JS checked in. They are not wired into the VM yet (no consumer exists).
- [ ] Tests: checker accept/reject cases, emitter golden files, and the resume-point
      report on the examples.
- [ ] `scripts/bgen.sh` (regenerate) and `scripts/bgen.sh --check` (freshness). Wire
      `--check` into `scripts/gate.sh` only if it is fast and does not need the network.
      Otherwise document it and skip it.

## Notes
- Keep the subset small (ARCH risk "Builtin language scope creep"): anything awkward
  becomes an intrinsic, not a language feature.
- The privileged syntax `%Name(args)` and `call_intrinsic` are defined in
  docs/compiler.md 7.3. If the emitter needs more (for example direct slot access),
  propose it in the log instead of inventing it.

## Log

2026-11-01 (infra)
- Implementation language (D1170): Rust, `crates/djs-bgen`, no dependencies, with its
  own subset parser and type checker. TypeScript 7.0.2 in pi-private ships only the
  native `tsc` (`node_modules/typescript/lib` has no compiler API), so option (b) would
  have meant pinning TS 5.x and needing node/npm to regenerate. Told the coordinator
  before building on it.
- tsc check of the branded numerics: `type i32 = number & { readonly __num?: "i32" }`
  (and `"u32"`) lets literals and `k + 1` through but rejects i32/u32 mixing, so
  `intrinsics.d.ts` brands them that way. `f64` stays `number`, so the implicit widening
  bgen allows also type-checks. tsc 7 type-checks `builtins/` cleanly with
  `builtins/tsconfig.json` (`lib: es5`, strict).
- Crate: lexer (JSDoc capture; clear errors for templates, BigInt, separators,
  octal), parser (only the subset; every rejected construct says what to use instead),
  checker (names, types, numeric rules, tags, definite return, one error per mistake via
  an internal error type), resume-point analysis (call sites in evaluation order;
  reentrancy as a least fixpoint over the call graph), JS emitter, report. Subset rules
  are in D1171 and builtins/README.md.
- Output format (D1172), a proposal for P1-2: one strict Script, an IIFE with every
  builtin as a local function, then `%InstallMethod(target, key, fn, length)` and
  `%InstallIntrinsic(name, fn)`. The VM implements those two as leaf intrinsics (declared
  at the end of intrinsics.d.ts). Open for P1-2: getters (`@getter`), symbol keys,
  constructors, and a way for the compiler's `call_intrinsic` id table to learn the
  names of JS-implemented intrinsics (bgen could emit that list).
- Examples: ToPrimitive, OrdinaryToPrimitive, GetMethod, ToNumber, ToString,
  ToIntegerOrInfinity, ToLength, LengthOfArrayLike, ArraySpeciesCreate, SameValueZero
  (leaf), Array.prototype.{forEach, map, indexOf, join, includes}.
- Tests: parser/lexer unit tests; `tests/checker.rs` (27 accept and 61 reject cases with
  messages and positions); `tests/golden.rs` (emitter and report golden files on a
  fixture with every construct, and a freshness test of builtins/gen); and
  `tests/behavior.rs`, which runs the generated prelude in qjs with JS stand-ins for
  the intrinsics and compares ~2860 calls of the five Array methods against qjs's native
  ones (results, error messages, proxy has/get/define trap order, species, mutation
  during iteration, ToPrimitive paths). A deliberately broken `join` gives 63 mismatches.
- Matching QuickJS's message for a non-constructor species needed the function's
  internal name, hence the `NewNotConstructorError` leaf intrinsic (D1173).
- `scripts/bgen.sh [--check|--report]`. The gate runs `--check` (0.2 s once built). I
  added that one line to `scripts/gate.sh`, as the issue asks, although gate.sh is not in
  `touches:`. No node or `.gitignore` change was needed.
- Proposed ARCH edits (not made, outside touches): ARCH says `cargo xtask bgen`; it is
  `scripts/bgen.sh`. And "branded number types ... so tsc checks them too" holds for
  i32/u32 mixing only; bgen is the authority on the numeric rules.

## Follow-ups
- P1-2: implement `%InstallMethod`/`%InstallIntrinsic`, compile `builtins/gen/prelude.js`
  in privileged mode, and confirm or adjust the format (D1172). bgen can also emit the
  list of JS-implemented intrinsic names for the compiler's `call_intrinsic` table.

  try/catch structure are there. Overflow checks for integer `+ - *` belong there (D1171).
- Language additions when real builtins need them, each as small as possible: rest
  parameters (`Function.prototype.call`), `switch`, constants at the top level.
