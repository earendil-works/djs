## Goal
Owner request: every reference to a repository file or directory in the guide (prose,
inline code like `crates/djs-core/src/heap/gc.rs`, tables, generated regions, diagrams'
captions) must be a link to that file on GitHub at the build commit (render::source_url,
D2102). Today only "Where to look" paths are enforced.

## Acceptance criteria
- [x] `djs-docs check` finds every inline-code or bare-text token that names an existing
      repo path (file or directory, also `path:line` / `path#symbol` forms if used) and
      fails if it is not a link; code blocks exempt (decide for gen:excerpt headers: they
      should carry a link too).
- [x] Either auto-link in the renderer (preferred if clean: inline code that is an
      existing repo path becomes a source link) or fix the sources; generated tables and
      regions link their paths too (fix the generators, not by hand).
- [x] References to paths that don't exist (renamed/removed files) fail the check.
- [x] Directories link to GitHub's tree view, files to blob view, at the build commit.
- [x] Built site checked: count of path mentions vs links before/after reported;
      `djs-docs check` and the overflow script green.

## Result
Every mention of a repository file or directory on the guide's pages is a link to GitHub
at the build commit, made by the renderer (D2104); `djs-docs check` fails on removed or
renamed paths, ambiguous partial paths, mislabelled links and any unlinked path left in
the rendered HTML. Excerpts carry a line-range link. Guide: 59/116 linked before,
117/117 after. Known gap: Markdown viewed on GitHub itself still shows plain inline code
(the linking happens on the site); excerpt line numbers change whenever lines above the
excerpt change (regenerated by merge-to-main's regen step).
