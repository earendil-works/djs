# 0076: Unicode normalization (String.prototype.normalize, localeCompare NFC)

status: done
agent: num

## Goal
`String.prototype.normalize` currently returns strings that need no tables unchanged and
throws "not supported yet" otherwise (0034, D1342), and `localeCompare` (no Intl) is a
code-point compare without the NFC step qjs applies. Codemode text processing (dedup,
comparisons of user/tool text) runs into this.

## Acceptance criteria
- [x] NFC, NFD, NFKC, NFKD from UCD 17 data (canonical/compatibility decomposition,
      canonical ordering, composition with the exclusion table, Hangul algorithmic),
      generated by the existing script with `--check` coverage. Quick-check fast paths
      (NFC_QC / NFD_QC) so already-normalized ASCII/Latin-1 text costs ~nothing.
- [x] Size: measure the tables in wasm (gzip too) against the 0043/0057 numbers; decide
      the default (on, or behind a cargo feature like \p{}, D1500) with numbers, and
      record the decision.
- [x] `localeCompare` normalizes to NFC first, like qjs. Behavior matches qjs on a
      generated corpus (including the NormalizationTest.txt conformance file from UCD:
      all lines pass).
- [x] test262 normalize tests pass; the difftest corpus gains a case; ratchets updated.

## Log
- Generated `unicode/norm_tables.rs` (gen-unicode.py `generate_norm`): decomposition varint
  stream (delta from the previous first target, runs of 1:1 consecutive mappings) with an
  index every 32 entries, composites as keys + i16 deltas, ccc runs, QC No/Maybe ranges.
  First encoding was 32.1K of stream; the delta/run coding brought it to 20.1K.
- `unicode/normalize.rs`: decompose (recursive, Hangul algorithmic), canonical order,
  compose; UAX #15 quick check. Unit test over all of NormalizationTest.txt plus
  invariance of every unlisted code point (~3 s in dev).
- string.rs: in-place ASCII/Latin-1 scan before copying units; quick check; result equal
  to the input returns the original Str. localeCompare NFC-normalizes both sides.
- wasm: +38.2K raw / +20.5K gzip; on by default behind `unicode-normalization` (D1760).
- qjs and djs both pass all 400,680 NormalizationTest checks (work/scratch/0076/nt.js);
  1 MB NFD/NFC/NFKC bench about as fast as qjs.

## Follow-ups
- normalize is a leaf and not suspendable; a multi-MB string normalizes in one step
  (~100 ms per MB of non-Latin-1 text in release). Same as the other string leaves.

## Result
`String.prototype.normalize` supports NFC/NFD/NFKC/NFKD for all strings (UCD 17), and
`localeCompare` normalizes to NFC first like qjs. Tables in `unicode/norm_tables.rs`
(generated, `--check` covered), algorithms in `unicode/normalize.rs`, feature
`unicode-normalization` on by default (D1760; turning it off restores the old throwing
behavior). test262 normalize + localeCompare all pass (4 ratchet entries removed);
corpus case `builtins/normalize.js`. The NormalizationTest unit test needs
`vendor/unicode/17.0.0/NormalizationTest.txt` in the primary checkout (fetched by
`scripts/gen-unicode.py`).
