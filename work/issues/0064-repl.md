## Goal
`djs repl`: an interactive REPL for debugging the engine and scripts, built only on the
public `Vm` API, so it runs in parallel with the engine work at little risk. djs's
distinguishing features should be first-class in it: suspension, fuel, heap images and
snapshots, bytecode, and the GC.

## Acceptance criteria
- [x] The read/eval/print loop: multi-line input (continue when the input is incomplete:
      unclosed brackets/strings/templates, detected via the compiler's "unexpected end
      of input" errors), history (persisted to a file), and Ctrl-C to abort a running
      evaluation (use fuel slices and check a flag between slices; djs can always stop
      between slices) and Ctrl-D to exit. Line editing: hand-rolled minimal, or a small
      well-known crate (record the choice: djs-cli is a std tool crate, AGENTS.md
      allows small deps there).
- [x] Persistent state across inputs: top-level `let`/`const`/`class`/functions persist
      (Script mode globals, D004), and top-level `await` works (decide how: for example
      compile each input as an async body when it contains `await`, with the
      declarations surviving; document the semantics and their gaps).
- [x] Printing results: completion values come with the lexer's 0058 (the Script
      completion value API). Until then, print the value of expression inputs, for
      example by compiling `expr` specially. Coordinate through the coordinator; switch
      to the real API when it lands. A readable value printer (objects, arrays, nested,
      cycles, functions, classes, symbols, errors with stack, Map/Set, typed arrays,
      promises with their state, BigInt, -0), host-side reading the heap. It need not
      match qjs (D1100: the codemode console is the prelude's).
- [x] Meta commands, for example: `.help`, `.load file`, `.ts on|off` (TypeScript),
      `.disasm <expr or function>` (bytecode via the existing disassembler), `.fuel [n]`
      (a fuel limit per input and the fuel used by the last input), `.gc` (collect,
      print heap stats), `.heap` (arena size, cells per kind), `.snapshot file` /
      `.restore file` (heap images: exactly djs's snapshot feature), `.step` or
      `.suspend-every n` (run in small fuel slices and show where it stops), `.time`,
      `.clear`.
- [x] Tests: drive the REPL non-interactively (stdin not a tty: line mode) in an
      integration test with scripted inputs and expected outputs, including multi-line,
      persistence, await, errors, and the snapshot/restore round trip.

## Log
- 2026-11-01 (repl): read the Vm API, the lexer and the heap readers. Everything the REPL
  needs is public (`vm.heap()`, the lexer, `disasm_template`, `strip_types`) except two
  things, added with the coordinator's OK (D1642): `Vm::run_metered` (fuel used) and
  `Vm::backtrace` (where a suspended call is), on two one-line `pub(crate)` getters in
  interp/run.rs (`Exec::fuel_left`, `Exec::pc`), plus a vm test.
- Line editor hand-rolled on `stty` with a stdin reader thread, so Ctrl-C is a byte the
  run loop polls between 1M-fuel slices (D1640). Tested under a pty (`script`): editing,
  history recall, multi-line, Ctrl-C at the prompt and during `for(;;){}`, Ctrl-D.
- Input plans (D1641): expression → `return [(input\n)];` async body; else Script; else,
  with `await`, a token-level rewrite that turns top-level declarations into assignments
  to globals declared by a Script first. TypeScript inputs are type-erased before the
  rewrite. Incomplete = the compile error sits at the end of the input.
- Printer: host-side, node `util.inspect` style, reads the heap only (no getters run).
- Meta commands: .help .exit .load .ts .disasm .fuel .suspend-every .time .gc .heap
  .snapshot .restore .clear. `.step` is covered by `.suspend-every` (prints the frame at
  every stop and continues in a VM restored from the image).
- Tests: tests/repl.rs (11 integration tests in line mode: expressions, persistence,
  multi-line, errors, await, printer, fuel/suspension, snapshot/restore across processes,
  meta commands, TypeScript, .load) and unit tests for the rewrite, dates and quoting.
  `--gc-stress` gives the same transcript as plain on a 35-input session.

## Result
`djs repl [--ts] [--gc-stress] [--no-history]` (crates/djs-cli/src/repl/, docs/cli.md).
- Interactive: a hand-rolled line editor with persistent history (`$DJS_HISTORY` or
  `~/.djs_history`), multi-line continuation, Ctrl-C to cancel a line or stop a running
  input, Ctrl-D to exit. Line mode (no prompts) when stdin is not a terminal.
- Inputs: expressions print their value (await works in them); Scripts keep their
  declarations as globals; top-level `await` in statements via the declaration rewrite.
- Printer: objects, arrays (holes), nesting depth 3, cycles, functions/classes/async/
  generators/bound, symbols, errors with stack, Map/Set/Weak*, typed arrays, ArrayBuffer,
  promises with state, BigInt, -0, Date, RegExp, boxed primitives, Proxy, getters
  unshown; line breaking at 72 columns.
- Commands: .help .exit .load .ts .disasm .fuel .suspend-every .time .gc .heap
  .snapshot .restore .clear.
- Vm additions: `run_metered`, `backtrace` (D1642).
Known gaps: statements print no value until 0058 (one switch, see Follow-ups); runtime
errors in expression inputs are 9 columns off on line 1; with top-level await, `const`
becomes `let` and statements print no value; the editor assumes one column per character
and has no completion; Unix terminals only (elsewhere line mode).
